# 2026-09-16

## 修复 deploy-backend.yml 两个运行时报错（首次实跑暴露）

### 坑1：备份步骤排在"离线"之前 → 文件被占用
- 报错：`ZipArchiveHelper : The process cannot access the file 'E:\test_iis\PMDVeg\Microsoft.OpenApi.dll'
  because it is being used by another process`（CompressArchiveUnauthorizedAccessError）。
- 根因：备份要**读** dll，但站点进程正锁着它们；而备份步骤当时排在 app_offline/停池之前。
- 修复：步骤顺序改为 **publish → 离线(含等待解锁) → 备份 → 复制 → 上线**。
- 新增"轮询等待解锁"：以 `[System.IO.File]::Open(..., FileShare::None)` 独占打开目标目录所有 *.dll，
  确认可写才继续，最多等 `LOCK_WAIT_SECONDS`（默认 60s，新 env 变量），超时 exit 1。

### 坑2：`Start/Stop-WebAppPool` 报 IIS 驱动器不存在
- 报错：`start-webitem : Cannot find drive. A drive with the name 'IIS' does not exist.`
- 根因两条叠加：
  1. `shell: powershell` 在自托管 runner 上落的是 **Windows PowerShell 5.1**（报错路径
     `C:\Windows\system32\WindowsPowerShell\v1.0`），不是 pwsh 7；
  2. 5.1 的 WebAdministration 模块依赖 `IIS:` 驱动器，runner **非管理员**时建不起来。
- 修复：改用 `C:\Windows\System32\inetsrv\appcmd.exe`（`appcmd stop apppool /apppool.name:XXX`）为首选；
  WebAdministration 降为兜底且**先 `Get-PSDrive -Name IIS` 判断存在**再调用；两者都失败也不中断，
  自动降级为只用 app_offline.htm。上线步骤同理。
- 新增诊断：Runner info 步骤打印 `PowerShell version` 与 `Running as admin: True/False`，
  一眼看出 runner 有没有管理员权限（停池要生效必须管理员：`svc.cmd uninstall/install/start` 换账号）。
