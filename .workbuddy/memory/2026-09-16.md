# 2026-09-16

## 修复 deploy-backend.yml 两个运行时报错（首次实跑暴露）

### 坑1：备份步骤排在"离线"之前 → 文件被占用
- 报错：`ZipArchiveHelper : The process cannot access the file 'E:\test_iis\PMDVeg\Microsoft.OpenApi.dll'
  because it is being used by another process`（CompressArchiveUnauthorizedAccessError）。
- 根因：备份要**读** dll，但站点进程正锁着它们；而备份步骤当时排在 app_offline/停池之前。
- 修复：步骤顺序改为 **publish → 离线(含等待解锁) → 备份 → 复制 → 上线**。
- 新增"轮询等待解锁"：以 `[System.IO.File]::Open(..., FileShare::None)` 独占打开目标目录所有 *.dll，
  确认可写才继续，最多等 `LOCK_WAIT_SECONDS`（默认 60s，新 env 变量），超时 exit 1。

### 坑2：`Start/Stop-WebAppPool` 报 IIS 驱动器不存在
- 报错：`start-webitem : Cannot find drive. A drive with the name 'IIS' does not exist.`
- 根因两条叠加：
  1. `shell: powershell` 在自托管 runner 上落的是 **Windows PowerShell 5.1**（报错路径
     `C:\Windows\system32\WindowsPowerShell\v1.0`），不是 pwsh 7；
  2. 5.1 的 WebAdministration 模块依赖 `IIS:` 驱动器，runner **非管理员**时建不起来。
- 修复：改用 `C:\Windows\System32\inetsrv\appcmd.exe`（`appcmd stop apppool /apppool.name:XXX`）为首选；
  WebAdministration 降为兜底且**先 `Get-PSDrive -Name IIS` 判断存在**再调用；两者都失败也不中断，
  自动降级为只用 app_offline.htm。上线步骤同理。
- 新增诊断：Runner info 步骤打印 `PowerShell version` 与 `Running as admin: True/False`，
  一眼看出 runner 有没有管理员权限（停池要生效必须管理员：`svc.cmd uninstall/install/start` 换账号）。

## 坑3：appcmd 失败后整个 step 仍判失败（$LASTEXITCODE 残留）
- 现象：日志走到 `All dll files are writable now`（锁已释放），最后仍 `Error: Process completed with exit code 1`，
  备份/复制被跳过。
- 原因：GitHub `shell: powershell` 会在脚本末尾自动 `exit $LASTEXITCODE`；
  appcmd 失败返回 **1168**（`ERROR ( message:Configuration error ... redirection.config ... insufficient permissions`），
  后续 PowerShell cmdlet 不刷新该变量 → 1168 被当作 step 退出码。
- 修复：容错分支显式 `$global:LASTEXITCODE = 0`（共 4 处：stop 失败、start 失败、offline 成功末尾、online 末尾）。
- **反直觉坑（实测）**：不要写 `& $appcmd ... 2>&1 | Write-Host` 想吞 stderr。
  PS 5.1 + `$ErrorActionPreference='Stop'` 下，`2>&1` 会把原生命令 stderr 转成 ErrorRecord 并**终止脚本**
  （本机 sim 测试：脚本停在第一行）。让 stderr 原样输出即可，GitHub 上实测不中断。
  → 已在 yml 注释里写明"不要这样写"。
- 注意：本机 PowerShell 工具沙箱里 `cmd /c exit N`、`findstr` 等非零退出的原生命令都会让脚本停在第一行，
  无法可靠模拟，验证此类问题要看 runner 真实日志。

## 实测结论
- `app_offline.htm` **单独就能释放 dll 锁**（in-process 托管下 ANCM 也生效）：
  日志 `Still locked: ... waiting 3s` → 下一轮 `All dll files are writable now`。
- 所以 runner 非管理员也能发布成功；`IIS_APP_POOL` 保留仅为有管理员时更彻底，置空可消除 appcmd 报错日志。
- venv python + PyYAML 校验 YAML；把每个 step 的 run 导出 .ps1 后用
  `Parser.ParseFile` 检查语法（本机 PowerShell 5.1.19041，与 runner 同版本）。19 个脚本全 OK。
- Bash 工具禁止调用 powershell（安全策略），必须拆成 Bash 导出 + PowerShell 工具解析两步。
