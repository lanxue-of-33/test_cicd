## 坑：PowerShell 内联脚本中文编码导致 ParserError
- 自托管 Windows runner（中文系统，默认 GBK 代码页）会用 GBK 读取 GitHub Actions 生成的 UTF-8 `.ps1`。
- 内联 `run:` 中若含中文**字符串字面量**（如 `Write-Host "未找到...跳过备份"`），`或`/`，`/`跳过` 等字符的 UTF-8 字节被误读后会生成破坏引号的字节，
  报 `The string is missing the terminator: "."` / `Missing closing '}'`。与业务逻辑无关。
- 修法：把所有内联 PowerShell 的**字符串字面量**改成 ASCII（日志用英文），注释/step 名称里的中文不受影响。
- 备份逻辑按用户要求改为：仅打包 `index.html` + `assets`，压缩包名以 `front_` 开头（`front_yyyyMMdd_HHmmss_commitSha.zip`）。

## 关键坑：web.config 覆盖会导致前端白屏
- 服务器 `E:\test_iis\PMDVeg\web.config` 是**手工定制**的：`path="api/*"`、`path="swagger/*"` 才交给 AspNetCoreModuleV2，
  其余静态文件交给 IIS 原生处理。
- `dotnet publish` 生成的默认 web.config 是 `path="*"` 全接管 → 覆盖后前端 index.html/assets 被后端接管 → 白屏。
- 解法：`SKIP_WEB_CONFIG: 'true'`，复制时跳过 web.config；仅当服务器无 web.config（首次部署）时才复制。

## 坑：YAML 里 step name 含「冒号+空格」会解析失败
- 写 `- name: Publish: copy output to IIS directory` → PyYAML 报 `mapping values are not allowed here`（第139行）。
- 必须加引号：`- name: 'Publish - copy output to IIS directory'`。中文冒号后无空格反而安全（前端文件里 `name: 发布:复制...` 没报错）。
